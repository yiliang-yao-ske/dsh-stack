# Agent 任务文件夹规范

> **一句话**：一个文件夹 = 一个 Agent 的可见边界 = 一个职责 = 一份最小输入 = 一个明确输出。

> **Agent 上下文公式**：自己的文件夹 + 一个主 Prompt + 一个最小输入包。超出这个范围的读取，都视为越界。

这份规范约束仓库里的 Agent 任务文件夹如何组织、如何加载 Prompt、如何与其他 Agent 协作。目标是让每个 Agent 都能**独立加载、独立执行、独立验收、独立替换**，而不是靠“读一下别的文件夹”来补上下文。

---

## 1. 为什么要原子化

Agent 的能力上限，往往不是模型不够强，而是上下文给得太杂：

- 把多个 Agent 的 Prompt 混在一起，角色和边界会打架。
- 让 Agent 去别的文件夹找资料，等于把隐式依赖藏进了文件系统。
- 共享可变数据、共享执行顺序，会让结果不可复现。
- 输入范围太大，Agent 会做超出任务范围的判断。

所以采用**有限视野 + 有限任务 + 显式交接**：

1. 每个 Agent 只看到自己文件夹里的内容。
2. 每次只加载一个主 Prompt。
3. 只接收当前任务所需的最小输入包。
4. 只产出约定好的输出。
5. 需要别的信息时，返回 `BLOCKED` 或提出请求，而不是自己去别的文件夹拿。

---

## 2. 核心原则

### 2.1 原子化

一个 Agent 任务文件夹是一个**原子单元**：

- 它包含完成该类任务所需的全部 Prompt、模板、示例和说明。
- 它不依赖其他 Agent 文件夹里的文件、数据或运行状态。
- 它可以被单独复制、单独加载、单独测试、单独替换。

### 2.2 有限视野

Agent 的可见范围应限定为：

- 本文件夹内的 README、Prompt、模板、示例。
- 本次任务显式提供的输入包。
- 与任务直接相关的契约片段、业务规则、环境信息。
- 明确的输出路径与输出格式。

**最小必要测试**：如果去掉某份信息，输出不会变，那这份信息就不应该给。

### 2.3 Prompt 即任务合同

Prompt 不是“背景介绍”，而是 Agent 的任务合同。它必须写清：

- 角色
- 目标
- 单次任务范围
- 非目标 / 禁止事项
- 必填输入
- 执行步骤（仅限本任务内的思考与产出步骤）
- 输出格式
- 质量门禁
- 停止条件与升级方式

### 2.4 显式交接

Agent 之间不直接读对方的文件夹。所有协作都通过**显式输入输出**完成：

- 上游 Agent 产出结构化文件。
- 编排器把文件路径/内容作为输入包的一部分传给下游。
- 下游 Agent 只读输入包，不读上游 Agent 的目录。
- 下游需要补充信息时，返回 `BLOCKED` 或 `NEED_INPUT`，由编排器补充。

---

## 3. Agent 的可见范围

| 可见 | 不可见 |
|---|---|
| 本文件夹内的 README、Prompt、模板、示例 | 其他 Agent 文件夹内的任何文件 |
| 本次任务的输入包 | 其他 Agent 的 Prompt、输出、内部文档 |
| 与任务直接相关的契约/规则片段 | 整个仓库的无关代码与文档 |
| 测试环境地址、账号、夹具说明 | 其他任务的数据与历史输出 |
| 输出路径与输出格式 | 生产密钥、真实 PII、无关敏感信息 |

> 物理上在同一个仓库，不代表逻辑上可见。文件夹边界就是 Agent 的上下文边界。

---

## 4. 原子化要求（必须满足）

### A1. 自包含

- 完成该类任务所需的 Prompt、模板、示例、输入说明都在本文件夹内。
- 不允许出现“去某个共享目录找模板”这种隐式依赖。
- 允许引用本文件夹内的相对路径文件；不允许引用其他 Agent 文件夹。

### A2. 无跨文件夹引用

- 不允许 `../other-agent/...` 这类路径。
- 不允许绝对路径指向其他 Agent 文件夹。
- 不允许在 Prompt 里写“参考另一个文件夹的 README/Prompt/用例”。
- 不允许通过软链接把其他 Agent 的内容挂进来。

### A3. 无共享可变状态

- 不共享可写的数据库、缓存、临时文件、运行目录。
- 不依赖“另一个 Agent 先跑过”的副作用。
- 需要共享的数据必须变成**只读输入包**，由编排器显式传入。

### A4. 单一职责

- 一个文件夹只负责一类任务，例如“写用例”“执行用例”“生成报告”。
- 不把“写用例 + 执行 + 修用例”塞进同一个 Agent。
- 职责边界写在文件夹 README 的第一段。

### A5. 单次单对象

- 一次任务只处理一个最小对象：一个 operation、一个 endpoint、一条链路、一个写接口 + 一种机制。
- 不要求一个 Agent 一次处理整个 API 或整个需求。
- 对象范围写进输入包，由编排器切片。

### A6. 显式输入输出

- 输入包必须有固定字段，不能靠 Agent 猜。
- 输出必须有固定格式、固定路径、固定状态。
- 状态至少包含：`done`、`partial`、`blocked`。
- 输出中必须区分：结论、证据、假设、缺口、未决问题。

### A7. 可重复

- 同一输入包，多次运行应得到结构一致的结果。
- 不依赖执行顺序、不依赖时间、不依赖其他 Agent 的临时状态。
- 数据使用唯一后缀，输出可覆盖或可版本化。

### A8. 最小权限与安全

- 只读优先；确需写入时，只写自己的输出目录。
- 不读取其他 Agent 的输出目录。
- 不包含生产密钥、真实 PII、破坏性 payload。
- 高风险任务（安全、资金、幂等）必须有明确授权和沙箱约束。

## 5. Prompt 加载规则

1. **一次只加载一个主 Prompt。** 不要把同一文件夹里的多个角色 Prompt 同时塞给一个 Agent。
2. **Prompt 必须自包含。** 它不能要求 Agent 去其他文件夹找上下文。
3. **Prompt 不能引用其他 Agent 的文件名、路径或输出。**
4. **Prompt 内的“上游/下游”只能是角色和交付物描述，不能是文件路径依赖。**
5. 如果一个文件夹是“套件”（包含编排 Prompt + 多个专用 Prompt），则：
   - 每次运行只加载其中一个；
   - 编排 Prompt 可以在**同一文件夹内**引用专用 Prompt 的文件名；
   - 专用 Prompt 不得反过来引用编排 Prompt 或其他专用 Prompt 的文件；
   - 一旦某个专用 Prompt 被拆到独立文件夹，必须去掉对同套件其他文件的路径引用。

### Prompt 最小结构

```text
# <任务名> Prompt

## 0. 任务声明
角色 / 唯一任务 / 单次范围 / 非目标

## 1. 启动检查
必须拿到的输入；缺失时怎么办

## 2. 输入
字段、含义、是否必填

## 3. 步骤
只描述本任务内的分析与产出步骤

## 4. 输出
文件路径、章节、字段、状态

## 5. 质量门禁
可判定的完成标准

## 6. 停止条件
什么情况下返回 blocked，不要编造
```

## 6. 推荐目录结构

```text
<agent-task-folder>/
├── README.md              # 职责、边界、输入输出、加载方式
├── prompt.md              # 主 Prompt（或 prompts/ 下的单角色 Prompt）
├── input.schema.yaml      # 可选：输入包字段约束
├── output.schema.yaml     # 可选：输出字段约束
├── templates/             # 可选：本任务专用模板
└── examples/              # 可选：本任务专用示例
```

要求：

- `README.md` 第一段必须写清“这个 Agent 做什么、不做什么”。
- 模板和示例只能服务本文件夹的职责，不能变成跨 Agent 的共享库。
- 如果确实需要共享库，应把共享内容**复制**进各文件夹，或由编排器作为输入包传入；不要建立跨文件夹引用。

## 7. 文件夹之间如何协作

### 7.1 只通过输入包交接

编排器向下游 Agent 传递：

```yaml
task_id: TASK-...
input_artifact:
  type: case_package | spec_excerpt | run_request
  path: "/abs/or/relative/path"
  content: "可选：直接内联"
constraints:
  max_items: 20
  allowed_actions: read-only | sandbox-write
output_path: "..."
```

下游 Agent 只读 `input_artifact`，不读上游 Agent 的目录。

### 7.2 需要更多信息时

- 返回 `status: blocked`，列出缺少什么、为什么阻塞。
- 返回 `status: partial`，先交付能做的部分，把不能做的标 `BLOCKED`。
- **不要**自己去其他文件夹搜索、猜测或拼接上下文。

### 7.3 不允许的行为

- 直接读写其他 Agent 文件夹。
- 把其他 Agent 的输出当成“默认存在”。
- 依赖其他 Agent 的运行顺序或临时文件。
- 在 Prompt 里写“先看 ../xxx 目录”。

## 8. 当前仓库的落地方式

```text
backend-api-test-write/          # 只写测试用例，不执行
├── README.md
├── backend-api-testcase-orchestrator.md
├── backend-api-contract-testcase-write.md
├── backend-api-parameter-testcase-write.md
├── backend-api-e2e-testcase-write.md
├── backend-api-idempotency-testcase-write.md
└── backend-api-security-testcase-write.md

backend-api-test-code-go/        # 只写 Go 测试代码，不执行完整测试
backend-api-test-code-python/    # 只写 Python 测试代码，不执行完整测试

backend-api-test-execute-go/     # 只执行 Go 测试，不写用例/代码
backend-api-test-execute-python/ # 只执行 Python 测试，不写用例/代码
```

- `backend-api-test-write` 是“写用例套件”，每次运行只加载其中一个 Prompt。
- `backend-api-test-code-go` / `backend-api-test-code-python` 是“写代码套件”，只做编译/收集级验证，不判定业务结果。
- `backend-api-test-execute-go` / `backend-api-test-execute-python` 是“执行套件”，每次只接收一个任务包。
- 执行 Agent 的输入是 case package、测试代码路径、运行配置；输出是结果包、报告和证据。
- 各文件夹不引用其他 Agent 文件夹，也不依赖外部 Prompt；只通过编排器传递结构化产物。
- 测试代码由代码 Agent 产出，执行 Agent 只消费、不生成、不修改。

## 9. 新增 / 修改 Agent 文件夹的检查清单

- [ ] 文件夹只有一个明确职责
- [ ] README 第一段写清了“做什么 / 不做什么”
- [ ] 完成该任务所需的 Prompt、模板、示例都在本文件夹内
- [ ] 没有 `../` 指向其他 Agent 文件夹
- [ ] 没有绝对路径指向其他 Agent 文件夹
- [ ] 没有“参考另一个文件夹”的文字
- [ ] 每次只加载一个主 Prompt
- [ ] 输入包字段固定、必填项明确
- [ ] 输出路径、格式、状态明确
- [ ] 有质量门禁和停止条件
- [ ] 不依赖其他 Agent 的运行状态或共享可变数据
- [ ] 不包含生产密钥、真实 PII、破坏性 payload
- [ ] 通过“盲测”：只给本文件夹 + 一个最小输入包，Agent 能独立完成
- [ ] 通过“最小化测试”：删掉非必要输入，输出不应改变

## 10. 反例

| 反例 | 问题 |
|---|---|
| Prompt 里写“参考 `../backend-api-test-execute/README.md`” | 跨文件夹引用，下游文件夹一移动就失效 |
| Agent 主动去别的目录找用例/模板 | 视野越界，依赖隐式存在 |
| 两个 Agent 共享一个可写 fixtures 目录 | 共享可变状态，结果不可复现 |
| 一个 Prompt 同时负责“写用例 + 执行 + 修用例” | 职责不单一，失败无法归因 |
| 输入包直接塞整个仓库 | 上下文过载，Agent 容易做范围外判断 |
| 输出依赖“另一个 Agent 先跑完” | 隐式顺序依赖，无法单独执行 |
| 把其他 Agent 的输出当作默认输入 | 缺少显式交接，无法审计 |

## 11. 审计方法

### 11.1 盲测

把目标文件夹复制到临时目录，只提供：

- 本文件夹内容
- 一个最小输入包
- 一个输出路径

然后运行。如果 Agent 需要读取文件夹外的任何东西才能完成，说明原子化不达标。

### 11.2 引用扫描

```bash
# 扫描明显的跨文件夹路径；路径穿越 payload 等业务字符串需人工排除
grep -RInE '\.\./|/Users/|/home/|backend-api-test-execute' <agent-folder>
```

检查 Markdown 链接、代码块中的路径、Prompt 里的“参考/参见”措辞。

### 11.3 最小化检查

对输入包逐项删除，观察输出是否变化：

- 不变：该项不是必需信息，不应提供。
- 变化：该项是必要输入，应写进输入契约。

### 11.4 单 Prompt 检查

统计本次运行实际加载的 Prompt 数量。超过一个主 Prompt，或同时加载多个角色，视为不达标。

---

## 12. 结论

原子化不是把文件拆得越碎越好，而是保证：

> **一个 Agent 只需要自己的文件夹 + 一个最小输入包，就能完成一个边界清晰的任务，并产出可被下游直接消费的结果。**

只要这条成立，Agent 就可以被独立开发、独立测试、独立替换，编排器也只需要关心“给谁、给什么、收什么”，而不需要关心它内部读了什么。
